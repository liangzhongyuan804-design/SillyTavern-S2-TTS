# S2 TTS (s2.cpp) — SillyTavern 扩展

把酒馆里角色的回复文本交给本地 **s2.cpp**（Fish Audio S2-Pro GGUF）语音合成，再把生成的语音放回聊天界面播放。

全程本地推理，不联网、不上传任何对话内容。

仓库地址：<https://github.com/liangzhongyuan804-design/SillyTavern-S2-TTS>

---

## 功能

- **自动朗读**：新回复生成完毕后自动合成并播放。
- **播放打断与排队**：新回复到来时自动停掉正在播的旧音频；用户发消息时停止朗读；手动点几条回复是**排队朗读**，不会叠在一起。
- **流式播放**：边合成边出声，第一段音频不必等整句生成完。服务端 1.5 秒吐出第一块，页面里实测 2.4 秒就能听到声音（不开流式要等 23.7 秒）。
- **持久化缓存**：合成好的音频存在酒馆数据目录的磁盘上。同一条回复再听一次是**零延迟**——刷新页面、重启酒馆都还在。
- **随时可停**：关掉页面、刷新、或中途再点一次朗读，正在进行的合成会立刻中断，不会白占着 GPU。
- **消息内朗读按钮**：每条角色消息的操作栏里有一个 🔊 按钮，点一下就朗读这一条。正在朗读时变成 ⏹（点击停止），排队中变成 🕐（点击取消）。
- **两种音色来源**
  - *已保存音色*：直接选音色文件（服务端 `--voice-dir` 目录下的 `.s2voice`，或 `.wav` / `.mp3` 录音）。
  - *参考音频*：上传一段参考音频 + 逐字转录，每次请求即时克隆音色。
- **自定义音色不用转格式**：把 `.wav` / `.mp3` 丢进音色目录、配一个同名的 `.txt` 逐字转录，它就能直接当音色用（也能被标签选中），不需要跑任何转换工具。
- **面板内一键生成 `.s2voice`**：音色树里点 ⬇，在波形上圈出要用的那一段、填好转录，扩展就调 `s2.exe --save-voice` 把录音变成档案存进音色目录（约 7 秒）。不用再敲命令行。
- **标签自动选音（三级分类）**：回复开头写 `小雅·女·妩媚·生气·：“你怎么才来！”`，扩展按 **性别 → 性格 → 语气** 三级在音色目录里找到对应的音色文件并用它来配音。**目录名就是标签**——新建一个文件夹等于新增一个可选项，不用改任何配置。
- **朗读区间**：可以指定只朗读消息里某一段，例如把 *朗读区间* 设成 `【朗读内容】`，那么只有 `【` 和 `】` 之间的内容会被念出来，动作描写、心理活动、系统提示全部跳过。
- **文本清洗**：自动去掉代码块、`<tag>` 标签、`*动作*`、Markdown 标记和表情，避免被念出来。
- **可调参数**：温度、Top P、Top K、最大 token、是否服务端按句拆分、句间停顿、播放速度。
- **一键管理服务进程**：如果 s2.cpp 还没跑，扩展可以直接启动/停止它（自动带上 CUDA DLL 目录）。
- **引擎日志**：扩展设置里能直接看 s2.cpp 的输出，编码失败等静默降级会明确弹警告。
- **斜杠命令**：`/s2tts` 朗读最后一条回复，`/s2tts 你好世界` 朗读指定文本。

## 架构

```
酒馆页面 (浏览器扩展)
   │  fetch /api/plugins/st-s2-tts/*   ← 同源，无 CORS 问题
   ▼
SillyTavern 服务端 (server plugin)
   │  ├─ 缓存命中？ ──► 直接回放磁盘上的 PCM（0.00x 秒，不碰 GPU）
   │  └─ 未命中
   │        │  multipart/form-data POST
   ▼        ▼
s2.cpp HTTP Server  (127.0.0.1:3030/generate)
   │  边生成边吐 PCM
   ▼
服务端插件同时把 PCM 落盘 → <数据目录>/<用户名>/s2-tts-cache/
```

浏览器扩展和服务端插件分成两半，是因为 **s2.cpp 不返回任何 CORS 响应头**，浏览器页面无法直接调用它。
把请求交给 SillyTavern 自己的服务端转发，既绕开了 CORS，也让扩展可以顺带管理 s2.cpp 进程。

| 文件 | 作用 |
|---|---|
| `plugin/index.js` | 服务端插件。转发 `/generate`（缓冲 / 流式两种模式）、探测服务状态、列出音色、启停 s2.cpp 进程、暴露引擎日志、管理持久化缓存。 |
| `plugin/cache.js` | 持久化缓存。缓存键计算、WAV 解析与重建、流式落盘、容量淘汰。无 SillyTavern 依赖，可单独测试。 |
| `plugin/voices.js` | 音色目录扫描（把三级分类读成一棵树）+ **ASCII 中转**：s2.cpp 用窄字符拼路径，中文目录名的音色它打不开，插件会先复制一份到纯 ASCII 目录再交给它。 |
| `plugin/profile.js` | 生成 `.s2voice` 档案。拼 `s2.exe --save-voice` 命令行、盯着进程输出、写档案、报告阶段（无 SillyTavern 依赖，可单独测试）。 |
| `index.js` | 浏览器扩展。消息钩子、朗读按钮、设置面板、请求编排。 |
| `player.js` | Web Audio 播放。流式 PCM 分块调度 + 缓冲模式解码 + 缓存重放 + 播放结束等待。 |
| `queue.js` | 朗读队列。串行播放、打断、取消（无 SillyTavern / 浏览器依赖，可单独测试）。 |
| `voicetree.js` | 标签解析与选音。纯函数：切出标签块、把标签归到性别/性格/语气、按标签挑音色（无 SillyTavern 依赖，可单独测试）。 |
| `profile.js` | 波形与 WAV 编码。纯函数：算波形峰值、把录音裁成 16 bit 单声道 WAV（无 SillyTavern 依赖，可单独测试）。 |
| `profile-ui.js` | 「录音 → .s2voice 档案」对话框：画波形、选区间、填转录、选目录、跟进度。 |
| `sanitize.js` | 纯文本清洗逻辑（无 SillyTavern 依赖，可单独测试）。 |
| `settings.html` | 设置面板模板。 |
| `style.css` | 样式。 |
| `manifest.json` | 酒馆扩展清单。**它在仓库根目录**，所以同一个仓库既能当浏览器扩展装，也能当服务端插件装。 |
| `package.json` | 仓库清单。`main` 指向 `plugin/index.js`——酒馆的插件管理器靠它找到服务端插件的入口。 |
| `install.mjs` / `install.ps1` / `install.sh` | 离线安装脚本（Node 版跨平台，PowerShell 版给 Windows）。 |

### 服务端插件的路由

| 路由 | 作用 |
|---|---|
| `POST /status` | 探测 s2.cpp 是否在监听且确实是 s2.cpp（靠 `X-Request-Start` 指纹判定）。 |
| `POST /generate` | 转发合成请求。`relay: "buffer"` 回传完整 WAV；`relay: "stream"` 把上游的 PCM 分块直接转发给浏览器。响应头 `X-S2-Encode-Failures` 表示本次请求发生了多少次参考音频编码失败，`X-S2-Cache` 表示这次是 `hit`（命中缓存）还是 `miss`（新合成）。 |
| `POST /voices` | 列出音色目录里的 `.s2voice` 和 `.wav` / `.mp3`。如果目录是三级分类结构（`voices/女/妩媚/生气.s2voice`），响应里还会带上整棵树（`entries` / `tree` / `names`），扩展据此把标签翻译成音色。 |
| `POST /voices/transcript` | 写录音的逐字转录（同名 `.txt`）。 |
| `POST /voices/audio` | 返回录音的原始字节，供扩展画波形、裁剪。只允许读音色目录里的文件。 |
| `POST /voices/profile` | 用 `s2.exe --save-voice` 生成 `.s2voice` 档案。立刻返回 `jobId`，进度用下一个路由查。 |
| `POST /voices/profile/status` | 档案生成任务的阶段（`starting` / `loading` / `encoding` / `saved`）、日志和结果。 |
| `POST /start` / `POST /stop` | 由插件拉起 / 关闭 s2.cpp 进程（自动拼好 CUDA DLL 目录和参数）。 |
| `POST /logs` | 返回 s2.cpp 的输出尾部、警告列表和编码失败计数。 |
| `POST /cache/stats` | 缓存条目数、占用字节数和目录位置。 |
| `POST /cache/list` | 缓存条目列表（最新在前）。 |
| `POST /cache/delete` | 删除单个条目。 |
| `POST /cache/clear` | 清空整个缓存。 |

### 流式链路

```
s2.cpp  --chunked PCM-->  服务端插件  --HTTP chunked-->  浏览器  -->  AudioBufferSourceNode
 (逐帧写)                (只读一次就转发)              (边到边播)
```

三个环节缺一不可，任意一环退化成"先攒完再发"，流式就白做了：

1. **s2.cpp**：必须 `chunked: true` + `output_format: "pcm_s16le"` +
   `stream_holdback_frames: 0`。最后一个参数是决定性的——默认的 holdback 等于
   Codec 的完整历史窗口，**最后一帧之前一个样本都不会吐**，响应看起来和缓冲模式一模一样。
2. **SillyTavern**：`src/server-main.js` 全局挂了 `compression()`，它会把整个响应攒起来压缩。
   插件的流式响应带 `Cache-Control: no-store, no-transform`，
   compression 的 `shouldTransform()` 看到 `no-transform` 会整个跳过。
3. **浏览器**：`player.js` 用 `response.body.getReader()` 边读边调度，
   每个 ~80 ms 的 PCM 片段交给一个 `AudioBufferSourceNode`，按精确的 `start(t)` 排队，
   所以片段之间没有接缝。

浏览器一旦离开（刷新、关页面、点停止），连接会断；服务端插件监听到响应关闭，
立刻 `abort()` 掉上游的 s2.cpp 请求，合成随即停止、显存释放。
这里有个容易踩的坑：客户端消失后 `res.write()` 会一直返回"缓冲区已满"，
而对应的 `drain` 事件**永远不会来**——如果转发协程只等 `drain`，它就会永远挂着，
连带把上游请求和显存一起吊住。所以转发同时等 `drain` 和"客户端已断开"两件事。

## 环境要求

- **SillyTavern ≥ 1.19**（服务端插件是 1.19 才有的功能）。
- **Node.js ≥ 20**（SillyTavern 自身的要求）。
- **s2.cpp** 已编译可用（见 [s2.cpp](https://github.com/rodrigomatta/s2.cpp)），以及对应的 GGUF 模型和 `tokenizer.json`。
- **显存**：模型常驻显存。实测 `s2-pro-q8_0`（5.3 GB）在 8 GB 卡上会让 s2.cpp 占用约 6.5 GB 显存，
  剩下的 1.5 GB 要留给桌面和浏览器。如果这个额度被抢走，s2.cpp 会在
  `failed to allocate graph, reserving` 上反复重试，表现为**请求卡住不返回**，
  同时引擎一直占着（后面的合成全部报「忙」）。合成时把吃显存的程序（游戏、视频播放器、
  其它 AI 进程）关掉即可。

## 安装

扩展由**两部分**组成，两部分都要装：

| 部分 | 装到哪里 | 干什么 |
|---|---|---|
| 浏览器扩展 | `<ST>/public/scripts/extensions/third-party/` | 面板、消息钩子、播放 |
| 服务端插件 | `<ST>/plugins/` | 转发合成请求、扫描音色目录、生成 `.s2voice` 档案、持久化缓存 |

服务端插件是 SillyTavern 1.19 才有的机制，而且**默认是关闭的**——
不开 `enableServerPlugins` 它根本不会被加载，扩展会一直报「连接失败」。

### 方式一：用扩展管理器装（推荐）

**第 1 步 · 装服务端插件。** 在**酒馆目录**里执行（`plugins.js` 是酒馆自带的插件管理器）：

```bash
node plugins.js install https://github.com/liangzhongyuan804-design/SillyTavern-S2-TTS
```

它会把仓库克隆到 `<ST>/plugins/SillyTavern-S2-TTS/`，
而且以后每次开机酒馆都会自动 `git pull` 更新它。

**第 2 步 · 装浏览器扩展。** 酒馆里：*扩展* → *安装扩展程序* → 粘贴同一个地址 → 安装。
弹窗里有两个按钮，区别只是克隆到哪儿：

| 按钮 | 落地目录 | 酒馆里显示的名字 |
|---|---|---|
| *给所有人安装* | `<ST>/public/scripts/extensions/third-party/SillyTavern-S2-TTS/` | `third-party/SillyTavern-S2-TTS` |
| *只给我安装* | `<ST>/data/<用户名>/extensions/SillyTavern-S2-TTS/` | `third-party/SillyTavern-S2-TTS` |

两种装法在酒馆里都是同一个名字，扩展是自定位的，所以随便挑一个就行。

> 浏览器扩展是**自定位**的：它用 `import.meta.url` 算出自己被装在哪个目录下，
> 所以仓库叫什么名字、装在哪个目录下都不影响，仓库改名也不用重装。

**第 3 步 · 打开服务端插件开关。** 在 `<ST>/config.yaml` 里加一行：

```yaml
enableServerPlugins: true
```

**第 4 步 · 重启 SillyTavern。** 服务端插件只在启动时加载。

### 方式二：一键脚本（离线，不想用 git 的话）

Windows（PowerShell）：

```powershell
cd SillyTavern-S2-TTS
.\install.ps1 -StRoot 'F:\你的\SillyTavern目录'
```

任何装了 Node 的地方（Linux / macOS / Windows 都行）：

```bash
node install.mjs --st /path/to/SillyTavern
# 或者
sh install.sh /path/to/SillyTavern
```

脚本会做三件事：

1. 浏览器扩展 → `<ST>/public/scripts/extensions/third-party/st-s2-tts/`
2. 服务端插件 → `<ST>/plugins/st-s2-tts/`
3. 在 `config.yaml` 末尾追加 `enableServerPlugins: true`（如果还没有的话）

然后**重启酒馆**。

> `enableServerPlugins` 默认是 **关闭** 的，不开这个开关服务端插件就不会被加载，
> 扩展会一直报「连接失败」。脚本已经自动帮你改好了。
>
> `install.ps1` 里的中文提示用的是 **UTF-8 + BOM**。如果你要改这个脚本，
> 请保持带 BOM 另存，否则 PowerShell 5.1 会按 ANSI 读取而报语法错误。
> （PowerShell 7+ 没有这个问题。）

### 方式三：手动

把两个部分分别拷过去：

```
（仓库根目录里的这些文件）
  manifest.json  index.js  player.js  queue.js  sanitize.js
  profile.js  profile-ui.js  voicetree.js  settings.html  style.css  locales/
        ->  <ST>/public/scripts/extensions/third-party/st-s2-tts/

plugin/     ->  <ST>/plugins/st-s2-tts/
```

然后在 `config.yaml` 里加上：

```yaml
enableServerPlugins: true
```

重启 SillyTavern。

## 配置

重启后打开 **扩展设置 → S2 语音合成**。

### 1. 服务地址

默认 `http://127.0.0.1:3030`。点 **测试连接**：

- ✅ *已连接* — s2.cpp 正常监听且确实是 s2.cpp 协议。
- ⚠️ *被其它程序占用* — 端口上有别的服务，换端口或先关掉它。

### 2. 音色

**方式 A：已保存音色**

1. 在 *音色目录* 里填 s2.cpp 启动时 `--voice-dir` 指向的目录，例如 `F:\s2\s2.cpp\voices`。
2. 点 **刷新**，下拉框会列出该目录下所有 `.s2voice` 文件（不含扩展名）。
3. 选一个即可。

**方式 B：参考音频（即时克隆）**

1. 切换到 *参考音频* 模式。
2. 选择一个音频文件（wav / mp3 / flac / ogg / m4a 都行，s2.cpp 内置了 dr_wav 和 dr_mp3 解码）。
3. 在文本框里填这段音频的**逐字转录**。这一步不能省——s2.cpp 需要它来提取音色特征，转录不准会明显影响合成质量。

> ⚠️ **参考音频必须短：5–15 秒。**
>
> 这一条是硬限制，不是建议。s2.cpp 的参考编码器会按音频长度分配计算图显存：
> 参考音频过长时，它会申请几百 GB 显存并触发 CUDA OOM，
> 然后 **静默地** 打印一句 `encode failed, running without reference audio`，
> 继续用默认音色把音频合成出来——HTTP 仍然是 200，听起来「像是成功了」，其实根本没克隆。
>
> 本机实测：`sao.wav` 其实是 **673 秒**的 MP3，编码时试图申请
> `426762.55 MiB`（约 417 GiB）显存直接 OOM；截取 **8 秒**后同样的命令
> 立刻成功，并生成了 `.s2voice` 音色文件。
>
> 扩展现在会捕获这个降级：一旦发生就会弹警告，并在 *引擎日志* 里留下记录。

### 3. 引擎日志

*引擎日志* 里点 **查看引擎日志**，可以看到 s2.cpp 的实时输出，
包括模型加载、Codec 后端选择、以及「参考音频编码失败」这类警告。
警告会被单独挑出来置顶，不会被 ggml 的显存重分配日志淹没。

### 4. 服务进程（可选）

如果 s2.cpp 还没跑，可以在 *服务进程* 里填好路径然后点 **启动服务**：

| 字段 | 说明 |
|---|---|
| `s2.exe` | 编译产物路径 |
| `GGUF 模型` | `s2-pro-q8_0.gguf` 之类 |
| `tokenizer.json` | 分词器路径 |
| `DLL 目录` | CUDA 运行库目录（`cublas64_*.dll` / `cudart64_*.dll` 所在处），会加进子进程 PATH |
| `CUDA 设备序号` / `GPU 层数` | `0` / `-1`（全部层卸载到 GPU） |
| `Codec 后端` | `Auto` / `Follow backend` / `CPU` |

> 也可以完全不管这一块，自己在命令行起 s2.cpp，扩展只负责连接。

### 5. 流式播放

| 字段 | 说明 |
|---|---|
| `流式播放` | 勾选后，服务端边合成边把 PCM 转发给浏览器，第一段音频立刻开始播。**默认开启**。 |
| `首包缓冲 (ms)` | s2.cpp 在发出第一批字节前先攒多少毫秒的音频。默认 300；调小＝更早出声，调大＝首批音频更完整。 |

> **流式模式下，服务端的「按句拆分」会被强制关闭。**
> 按句拆分是"先合成完整一句、再推音频"，正好和流式相反，开着就等于又变回缓冲模式。
> 面板里那一项在流式开启时会被自动忽略，句间停顿也就没有了。

关掉流式播放会自动退回缓冲模式（整段 WAV 一次性返回再播放），
老版本 s2.cpp 不支持流式参数时也是这样兜底，行为和之前完全一致。

**本机实测（Debug 构建，RTF≈4）**：

| 参数 | 首包延迟 | 总时长 | 分块数 |
|---|---|---|---|
| 默认（`stream_holdback_frames` 缺省） | 12211 ms | 12212 ms | 5 |
| `stream_holdback_frames: 0` | **1508 ms** | 13587 ms | 15 |
| `low_latency: true`（stride=1） | 1408 ms | 29344 ms | 69 |

所以扩展固定用第二种：首包 1.5 秒，总时长不变。
第三种虽然首包更早，但解码批次从 15 涨到 69，总时长直接翻倍，不划算。

**真实酒馆页面里的 A/B 实测**（同一句文本、同一台机器）：

| 模式 | 控制台日志 | 首个声音 |
|---|---|---|
| 流式 | `[S2 TTS] synthesized 5.34s @ 44100 Hz (stream, first audio 2360ms, ctx=running)` | **2.4 秒** |
| 缓冲 | `[S2 TTS] synthesized 4.86s @ 44100 Hz (buffered, first audio 23737ms, ctx=running)` | 23.7 秒 |

差 **10 倍**。流式模式下 2.4 秒就能听到第一句，缓冲模式要等整段合成完。

### 6. 持久化缓存

| 字段 | 说明 |
|---|---|
| `启用持久化缓存` | 默认开启。关掉后每次都会重新合成。 |
| `缓存上限 (MB)` | 默认 512 MB。超了会自动删最旧的条目。 |
| `刷新` / `清空缓存` | 查看当前占用；或一键清空。 |

**缓存在哪里**：`<酒馆数据目录>/<用户名>/s2-tts-cache/`
（`F:\st-test\data\default-user\s2-tts-cache\`）。
每个条目是 `<key>.pcm`（裸 PCM 数据）加一个 `<key>.json`（采样率、文本、时间戳）。
按用户分目录，多用户酒馆互不串味。

**什么时候算命中**：缓存键 = `sha256(文本 + 音色 + 参考音频指纹 + 影响音频的生成参数)`。

- 换文本、换音色、换参考音频、换温度 / top-p / top-k / 最大 token / 是否按句拆分 → **不命中**，重新合成。
- 只改传输方式（开不开流式、首包缓冲多少毫秒、线程数）→ **仍然命中**，
  这些参数不参与缓存键，所以来回切换流式开关不会把缓存作废。

**Shift + 点击** = 强制重新合成，会绕过缓存。

**真实酒馆页面里的 A/B 实测**（同一句文本、同一台机器）：

| 场景 | 控制台日志 | 首个声音 |
|---|---|---|
| 第一次合成 | `synthesized 4.41s @ 44100 Hz (stream, first audio 2469ms, ctx=running, cache=miss)` | 2.5 秒 |
| **刷新页面后**再点 | `synthesized 4.41s @ 44100 Hz (stream, first audio 48ms, ctx=running, cache=hit)` | **48 毫秒** |

**差 51 倍**，而且第二次完全不占 GPU。

**为什么缓存在服务端**：服务端能在**动用 GPU 之前**就判断要不要合成；
浏览器侧的缓存只能等音频已经生成出来才帮得上忙。

> 一个已知的取舍：命中缓存时浏览器仍然要把参考音频（如果用了即时克隆）整个传一遍，
> 因为服务端要用它的指纹算缓存键。参考音频通常几百 KB，本机走回环网络是毫秒级，可以接受。

### 7. 播放打断与排队

朗读的行为规则：

| 触发 | 行为 |
|---|---|
| **新回复生成完毕**（自动朗读） | **打断**：停掉正在播的旧音频，清空队列，新回复优先。 |
| **你发了一条消息** | **停止**：朗读立刻停，队列清空——你在打字，不该有声音插进来。 |
| **开始新一轮生成** | 同样停止朗读，避免旧语音盖住生成过程。 |
| **手动点消息按钮** | **排队**：不打断当前播放，排在当前这条后面依次朗读。 |
| **`/s2tts 文本`** | 打断：显式点名的内容优先。 |
| **切换对话 / 滑动消息 / 删除消息** | 停止朗读并清空队列。 |

**按钮的三种状态**

| 图标 | 含义 | 点击后 |
|---|---|---|
| 🔊 | 空闲 | 开始朗读这一条（排队） |
| ⏳ | 排队中 | 从队列里取消这一条 |
| ⏹ | 正在朗读 | 停掉这一条（队列里其它条目保留） |
| ⏳ 转圈 | 正在合成 | 同样可以点击停止 |

播完之后按钮会**自动回到 🔊**（绿色），可以再点一次重播；
被中途打断也一样会复位——不会卡在「正在朗读」上导致这条再也点不动。

**关键实现点：「已调度」不等于「已播完」**

`AudioBufferSourceNode.start(t)` 只是把音频排进时间轴，函数返回时声音还在往外放。
如果拿"调度完成"当作"播完"，下一条会立刻开始——两条语音就叠在一起了。
所以 `player.waitForEnd()` 会一直等到**最后一个音频节点真正触发 `onended`**，
队列才放下一条。

另外 s2.cpp 同一时间只处理一个合成，队列同时保证了不会有两次合成并发（否则就是 503）。

**真实酒馆页面里的实测**（扩展在控制台打印 `queue: start` / `queue: done`）：

```
[S2 TTS] queue: start (mes=1)     ← 点第 1 条，开始合成
[S2 TTS] queue: done  (mes=1)     ← 第 1 条真正播完
[S2 TTS] queue: start (mes=0)     ← 第 2 条紧接着开始（两者相差 80 ms）
```

`done` 和下一个 `start` 之间只隔 **80 毫秒**，证明第二条严格等到第一条的音频节点
真正结束才开始——**不会叠音**。

点正在播放的那一条来打断，`done` 会在 **122 毫秒**后出现，而不是等音频放完：

```
[S2 TTS] queue: start (mes=1)
[S2 TTS] queue: done  (mes=1)     ← 122 ms，播放被立刻掐断
```

一次完整的打断（发消息 / 开始生成时触发）：

```
[S2 TTS] queue: start (mes=0)      ← 长音频开始合成
[S2 TTS] queue: dropped 1 job(s)   ← 打断：队列里那条被丢弃（永远不会响）
[S2 TTS] queue: done  (mes=0)      ← 23 ms 后，正在合成的那条也被中止
[S2 TTS] queue: start (mes=-)      ← /s2tts 打断测试 立刻开始新的朗读
```

前两行来自 `stopSpeaking()`，它由酒馆的 `GENERATION_STARTED` 事件触发——
也就是"你按下发送"的那一刻。

### 8. 标签配音（三级分类）

让角色回复里的**标签**决定用什么音色来念。

#### 标签长什么样

```
小雅·女·妩媚·生气·：“你怎么才来！”
 └名字 └性别 └性格 └语气 └ 台词
```

- 标签块必须在**回复的最开头**，用 `·`（U+00B7）分隔，以 `：` 结束。
- `·` 后面就是真正要朗读的台词，**标签本身永远不会被念出来**。
- 名字是可选的：`女·妩媚·生气·：“你好”` 一样能用。
- 三级也都是可选的：`女·：“你好”` 表示只限定性别。

#### 目录就是标签

音色目录按三层文件夹摆好，**文件夹名直接就是标签名**：

```
F:\s2\s2.cpp\voices\
├─ sao.s2voice                 ← 顶层文件：不在分类里，按原来的方式选
├─ 女\
│  ├─ 妩媚\
│  │  ├─ 生气.s2voice
│  │  ├─ 温柔.s2voice
│  │  └─ 默认.s2voice          ← 这一层没有对应音色时的兜底
│  ├─ 高冷\
│  │  ├─ 默认.s2voice
│  │  └─ 生气.s2voice
│  └─ 活泼\
│     ├─ 开心.s2voice
│     └─ 平静.s2voice
└─ 男\
   ├─ 阳光\
   │  ├─ 默认.s2voice
   │  └─ 开心.s2voice
   └─ 沉稳\
      ├─ 生气.s2voice
      └─ 平静.s2voice
```

- **新建一个文件夹 = 新增一个标签选项**，不用改任何配置、不用重启酒馆。
- 文件夹可以只建两层：`voices/女/生气.s2voice` 表示"女 · 生气"（跳过性格）。
- 叫 `默认`（或 `default`）的文件是那一层的兜底音色。

#### 怎么用

1. 按上面的样子把音色分好类，放进 s2.cpp 的 `--voice-dir` 目录。
   （没有现成的分类？跑一次 `make-demo-voice-tree.ps1 -VoiceDir '…'` 会生成一套样板结构。）
2. 扩展设置 → **音色** 里填同一个目录，点 **刷新**。
3. 扩展设置 → **标签配音** 里能看到**音色树**（点任意一个音色可以试听）和**可用标签速查表**（点标签名会填进试听框）。
4. 让角色回复带上标签就行：

```
小雅·女·妩媚·生气·：“你怎么才来！”
```

5. 控制台会打印选中的音色：

```
[S2 TTS] tag voice: 小雅 / 女 / 妩媚 / 生气 -> 女\妩媚\生气.s2voice (exact)
```

#### 匹配规则

标签是**从精确到宽松**逐级放宽的，保证永远能找到一个音色：

| 顺序 | 条件 | 例子 |
|---|---|---|
| 1 | 性别 + 性格 + 语气 全中 | `女·妩媚·生气` → `女/妩媚/生气.s2voice` |
| 2 | 性别 + 性格 中，语气换成该文件夹的 `默认` | `女·妩媚·开心` → `女/妩媚/默认.s2voice` |
| 3 | 只剩性别 | `女·高冷` → `女/高冷/默认.s2voice` |
| 4 | 性别下的任意音色 | `男·妩媚·生气` → `男/阳光/默认.s2voice` |
| 5 | 目录里随便挑一个 | — |
| — | 一条都没匹配上 | 用扩展设置里选的默认音色 |

#### 不认识的标签不会被误吃

只有当标签块里**至少有一个词命中已知分类名**（目录名 + 你在面板里自定义的词）时，
整段标签块才会被剥掉。其它情况（比如正文里出现 `·你好·世界·：`）**原样朗读**，
不会被切掉。想强制剥掉可以打开 *标签没匹配到任何音色时也照样剥掉*。

#### 自定义标签

**自定义标签** 折叠区里可以给每一级补充额外的名字（逗号分隔）。
音色还没做出来时也能先用这个标签写台词，等音色做好了自动生效。

#### 本机实测

真实酒馆页面（ST 1.19.0 + s2.cpp Debug 构建，RTF≈4）：

```
[S2 TTS] queue: start (mes=2)
[S2 TTS] tag voice: 小雅 / 女 / 妩媚 / 生气 -> 女\妩媚\生气.s2voice (exact)
[S2 TTS] synthesized 8.41s @ 44100 Hz (stream, first audio 2426ms, ctx=running, cache=miss)
[S2 TTS] queue: done (mes=2)
```

服务端缓存里那条记录的元数据，是「标签有没有被念出来」的直接证据：

```json
{
  "text": "“你怎么才来！我在这儿等你好久了。”",
  "voice": "F:\\s2\\s2.cpp\\voices\\女\\妩媚\\生气.s2voice"
}
```

`text` 里只有冒号后面的台词——`小雅·女·妩媚·生气·：` 整块被剥掉了；
`voice` 是那个中文目录下的 `.s2voice` 绝对路径。

> 缓存键里包含音色路径，所以**不同的标签会命中不同的缓存条目**，
> 同一句话换成 `女·高冷·` 会重新合成，不会串味。

#### 一个必须知道的坑：中文路径

s2.cpp 是用**窄字符**拼文件路径的，Windows 会用系统 ANSI 代码页转换它。
中文系统上这个代码页是 GB2312，所以**中文目录名在 s2.cpp 眼里是乱码**：

```
voice=F:\s2\s2.cpp\voices\女\妩媚\生气.s2voice
  → Pipeline error: failed to load voice profile 生气:
    cannot open voice profile: F:\s2\s2.cpp\voices\女\妩媚\生气.s2voice
  → HTTP 500
```

报错信息里的路径看着是对的（那只是原样打印的字符串），但文件是真打不开。

**扩展已经绕开了这个问题**：服务端插件会把这类音色**复制一份到纯 ASCII 目录**
（`<酒馆数据目录>/<用户名>/s2-tts-cache/voices/`），再把那个 ASCII 路径交给 s2.cpp。
原文件不会被改动，复制出来的内容和原件逐字节一致。

本机实测：

| 交给 s2.cpp 的路径 | 结果 |
|---|---|
| `F:\s2\s2.cpp\voices\女\妩媚\生气.s2voice` | ❌ HTTP 500，`cannot open voice profile` |
| `F:\s2tts-stage\a1b2c3d4.s2voice`（ASCII 中转） | ✅ HTTP 200，`Loaded voice profile: a1b2c3d4 (171 frames)` |

所以**目录名可以随便用中文**，只是中间多了一次拷贝（一个音色文件才几 KB）。

### 9. 朗读区间（只念标记里的内容）

可以指定**只朗读消息里某一段**，其余部分（动作、心理、系统提示）全部跳过。

扩展设置 → *行为* 里有一项 **朗读区间**，默认是 `朗读`（朗读整条消息）。
改成 `【朗读内容】` 之后，就只朗读 `【` 和 `】` 之间的内容：

```
【要念的话】这一段不会被念出来
```

**标记怎么写**：取值的**首尾两个字符**就是标记，中间那段只是给人看的名字，
真正决定行为的是首尾两个字符。所以下面三种写法完全等价：

| 写法 | 实际标记 |
|---|---|
| `【朗读内容】` | `【` … `】` |
| `【】` | `【` … `】` |
| `【{内容}】` | `【` … `】`（占位符写法，首尾字符更自由） |

想用别的符号就换首尾字符，例如 `「」`、`《》`、`| |`、`{}`。

**规则**

| 情况 | 结果 |
|---|---|
| 消息里有区间 | 只朗读区间里的内容 |
| 一条消息里有多个区间 | 全部朗读，中间用空格隔开 |
| 只写了开始标记、没写结束 | 从标记一直读到消息结尾 |
| 消息里根本没有区间 | 按 *找不到区间时仍然朗读整条消息* 这个开关决定（默认朗读整条） |

> **顺序**：先剥标签块，再取区间，最后做文本清洗。
> 所以 `小雅·女·妩媚·生气·：“【你好呀】”` 念出来的是「你好呀」，
> 标签和引号都不会被念到。
>
> **改区间会清掉内存里的音频缓存**：区间变了，同一条消息的朗读内容也变了，
> 旧音频必须作废。磁盘缓存不受影响——它按**最终送去合成的文本**寻址，
> 换了区间文本就变了，自然是新条目。

面板里的 *标签试听器* 会多显示一行 **朗读内容：…**，直接告诉你这段文本
实际会被念成什么样。

### 10. 自定义音色（直接用 .wav / .mp3）

音色目录里放 **`.s2voice`** 还是 **`.wav` / `.mp3`** 都可以当音色用，
不需要任何额外的转换工具。

**为什么要两种格式**

`.s2voice` **不是音频**，是 s2.cpp 的二进制音色档案（文件头 `S2VOICE`），
里面存的是参考音频**编码后的语义码 + 逐字转录**。加载它时 s2.cpp 不再碰音频，
所以最快、最稳——但它只能用 `s2.exe --save-voice` 生成。

`.wav` / `.mp3` 就是普通录音。s2.cpp 能**从参考音频现场克隆音色**
（`/generate` 的 `reference` + `reference_text`），所以它可以直接当音色用。

**怎么放**

```
voices/
├─ sao.s2voice
├─ 女/
│  ├─ 妩媚/
│  │  ├─ 生气.s2voice
│  │  └─ 温柔.wav          ← 录音
│  │  └─ 温柔.txt          ← 这段录音念出来的字（逐字转录）
│  └─ 活泼/
│     └─ 默认.wav
```

两个文件**同名**（只差扩展名）放在一起就行。

> **逐字转录是必须的**：s2.cpp 没有它就会拒绝合成（HTTP 400
> `Reference audio requires reference_text`）。
> 录音里说了什么，`.txt` 里就写什么，一字不差最好。

**转录可以在面板里写**

音色树里 `.wav` 条目右边有一个 `✎`，点它就能填转录，保存后自动写成同名的
`.txt`。没有转录的条目会标成红色的 **缺转录**，点它试听会直接告诉你缺什么。

扩展设置里的 *音色* 下拉框也会列出这些录音（按相对路径显示），
可以直接把它设成默认音色。

**标签选音一样能用**

`温柔.wav` 放在 `女\妩媚\` 里，回复开头写 `小雅·女·妩媚·温柔·：“你好”`
就会用它，规则和 `.s2voice` 完全一样。

**两种格式的差别**

| | `.s2voice` | `.wav` / `.mp3` |
|---|---|---|
| 生成方式 | `s2.exe --save-voice` | 直接放录音进去 |
| 每次合成 | 只加载档案，**快** | 重新编码参考音频，**慢一些** |
| 需要转录吗 | 不需要（档案里已经存了） | 需要（同名 `.txt`） |
| 换音色 | 重新生成档案 | 换个文件就行，**方便** |

所以：**自己做的音色直接用 `.wav`**，省去转换那一步；经常用、追求速度的
再转成 `.s2voice`。

**注意**

- 参考音频**太长会显存不足**。s2.cpp 会静默降级成「没有克隆音色」并返回 200，
  扩展会弹警告。**5–15 秒**最稳。
- `.wav` 走的是上传字节的通道，**中文文件名、中文目录都没问题**
  （`.s2voice` 不行，见 [8. 标签配音](#8-标签配音三级分类)）。

### 11. 面板内一键生成 .s2voice 档案

s2.cpp 只能从命令行存档案：

```powershell
s2.exe --model ... --tokenizer ... `
       --prompt-audio 参考.wav --prompt-text "这段录音念出来的字" `
       --voice 档案名 --voice-dir 音色目录 --save-voice
```

扩展现在直接替你做这件事。

**怎么用**

音色树里 `.wav` / `.mp3` 条目右边多了一个 **⬇**，点它：

1. 录音被读进浏览器，波形画出来
2. 在波形上拖出要用的那一段（默认取前 15 秒），也可以直接填秒数
3. 确认逐字转录（没有就现场写一个）
4. 选存放目录、填档案名
5. 点 **生成档案**

跑完音色目录里就多了一个 `.s2voice`，它是个普通音色：音色树里立刻能看到，
标签选音也能选中它（`女/活泼/录音.s2voice` 就用 `小雅·女·活泼·录音·` 命中）。

> **下拉框只列顶层档案**：*音色文件* 那个下拉框按 s2.cpp 的规矩只放音色目录**第一层**的
> `.s2voice`（因为它们是按 id 选的）。放进子目录的档案靠**标签**用；
> 想让它进下拉框，就把存放目录选成「（根目录）」。

**它做了什么**

| 步骤 | 在哪儿做的 |
|---|---|
| 读录音、画波形 | 浏览器（`AudioContext` 解码，WAV / MP3 都行） |
| 裁剪 | 浏览器（重编码成 44.1 kHz 单声道 16 bit PCM） |
| 存档案 | 服务端插件跑 `s2.exe --save-voice` |

**要知道的**

- **每次生成都要重新加载一遍模型**，实测约 **7 秒**
  （RTX 3060 Ti + s2-pro-q8_0，Debug 构建）。
  生成时**模型留在 CPU、只有编解码用 GPU**，所以不会跟正在跑的 s2.cpp 抢显存——
  服务器开着也能生成。
- 参考音频超过 15 秒容易显存不足（就是第 10 节那个坑），
  所以这里**必须裁**，超过 15 秒面板会给出警告。
- 生成好的 `.s2voice` 之后每次合成都直接加载它，**不用再编码参考音频**，比用 `.wav` 快。
- 档案名不能带路径分隔符；存放目录可以在下拉里选，三级分类目录会保留。
- 需要先在 **服务进程** 里填好 `s2.exe`、模型和 tokenizer 的路径。

**和手工敲命令的区别**

| | 面板一键生成 | 手工 `s2.exe --save-voice` |
|---|---|---|
| 裁剪 | 波形上拖 | 得自己先剪 |
| 转录 | 面板里填 | 命令行参数里写 |
| 分类目录 | 下拉选 | `--voice-dir` + `--voice` |
| 耗时 | ~7 秒 | ~7 秒 |

## 使用

- **自动朗读**：默认开启。每条角色消息渲染后自动排队合成并播放。
- **单条朗读**：消息操作栏的 🔊 按钮。再点一次会**强制重新合成**（参数或音色变了之后用这个）。
- **按标签选音**：回复开头写 `小雅·女·妩媚·生气·：“你怎么才来！”`，就自动用
  `voices\女\妩媚\生气.s2voice` 来念。详见 [8. 标签配音](#8-标签配音三级分类)。
- **只念标记里的内容**：把 *朗读区间* 改成 `【朗读内容】`，就只朗读 `【` 和 `】`
  之间的部分。详见 [9. 朗读区间](#9-朗读区间只念标记里的内容)。
- **自己做的音色**：把 `.wav` / `.mp3` 丢进音色目录，配一个同名的 `.txt` 转录，
  就能当音色用（也能被标签选中）。详见 [10. 自定义音色](#10-自定义音色直接用-wav--mp3)。
- **斜杠命令**：
  - `/s2tts` — 朗读最后一条回复。
  - `/s2tts 想说的话` — 朗读任意文本。

生成的音频会按消息 id 缓存在内存里，重复播放不再重新合成；切换对话或滑动消息会清掉缓存。

> **Shift + 点击** = 强制重新合成（跳过内存缓存和磁盘缓存）。
> 普通的自动朗读只跳过内存缓存——磁盘缓存按文本内容寻址，文本一样结果就一样，
> 所以重新生成出一模一样的回复时依然能命中缓存、瞬间出声。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 「连接失败」/ 状态一直显示未连接 | `enableServerPlugins` 没开，或者 `<ST>/plugins/` 目录没放对。服务端插件必须放在 **SillyTavern 根目录**下的 `plugins/`，不是 `public/scripts/extensions/`。 |
| 面板直接报错说「服务端插件没有加载」 | 服务端插件没装或没启用。在酒馆目录执行 `node plugins.js install <仓库地址>`，在 `config.yaml` 里加上 `enableServerPlugins: true`，重启酒馆。 |
| 要等很久才听到声音 | 多半是 *流式播放* 没勾。看浏览器控制台的 `[S2 TTS] synthesized …` 那行：`first audio 23737ms` 说明走的是缓冲模式，`first audio 2360ms` 才是流式。勾上后首包能快 10 倍。 |
| 控制台显示 `ctx=suspended` | 浏览器把 AudioContext 挂起了（自动播放策略）。随便点一下页面再朗读即可。 |
| 同一句话每次都重新合成，缓存不生效 | 控制台那行会显示 `cache=miss`。缓存键包含文本、音色、参考音频和生成参数——改过其中任何一项都会重新合成；Shift + 点击也会强制绕过缓存。 |
| 缓存占用越来越大 | 缓存上限默认 512 MB，超了会自动删最旧的条目。想清空就在 *持久化缓存* 区块点「清空缓存」。 |
| 提示「服务端没有可用的缓存目录」 | 服务端插件没有拿到用户数据目录（多半是酒馆版本太老，没有 `enableServerPlugins`）。缓存会被自动跳过，合成不受影响。 |
| 提示 `ECONNREFUSED` / 连不上 s2.cpp | s2.cpp 没启动，或端口和 *服务地址* 不一致。 |
| 提示「被其它程序占用，不是 s2.cpp」 | 端口上有别的服务（常见于 ComfyUI 插件也在用 3030）。两边只能留一个在监听，或者给其中一个换端口。 |
| 提示 *s2.cpp 正在忙*（HTTP 503） | s2.cpp 同一时间只处理一个合成请求。服务端插件会自己排队重试（0.5 / 1 / 2 / 3 / 5 / 8 / 12 秒），扩展还有一层退避重试；只有机器上**另一个程序**也在用同一个 s2.cpp 时才会真的失败。 |
| 提示「尚未选择音色」 | 没选音色，或者音色目录填错、该目录里没有 `.s2voice` / `.wav` / `.mp3` 文件。 |
| 标签选了但音色没变 | 控制台看 `[S2 TTS] tag voice:` 那行：如果压根没打印，说明回复里的标签块没被识别（标签必须在回复**最开头**，用 `·` 分隔、以 `：` 结束，而且至少有一个词要命中已知分类名）。也可以在 *标签试听器* 里输入同一段文本验证。 |
| 标签识别了，但挑的音色不是想要的 | 匹配是从精确到宽松逐级放开的：三级没全中时会退到该文件夹的 `默认`。把目标文件放在正确的层级，或把兜底文件改名为 `默认`。 |
| `.wav` 音色提示「缺少逐字转录」 | s2.cpp 克隆音色必须知道录音里说了什么。在同一个文件夹放一个**同名**的 `.txt`（只差扩展名），里面写这段录音念出来的字；也可以在音色树里点 `✎` 直接写，面板会帮你存成那个 `.txt`。 |
| `.wav` 音色听起来和录音不像 | 转录和录音对不上，或者录音太短、含背景音乐。转录要一字不差。 |
| `failed to load voice profile ... cannot open voice profile` | s2.cpp 用窄字符拼路径，中文目录名在它眼里是乱码。扩展会自动复制一份到 ASCII 目录再交给它；如果日志里仍然出现这个错误，说明中转目录本身也带了中文（例如酒馆数据目录在中文路径下），把酒馆数据目录挪到纯英文路径即可。**这只影响 `.s2voice`**——`.wav` 走的是上传字节的通道，中文路径完全没问题。 |
| 标签里的音色没生效 | *参考音频*模式下标签**不会**替换参考音频（那是你显式上传的克隆音色）。切回 *已保存音色* 模式即可。 |
|  设了朗读区间却还是念了整条 | 消息里必须有对应的标记。`【朗读内容】` 配的是 `【` … `】`，消息里要真的写 `【…】`。也可以打开 *找不到区间时仍然朗读整条消息* 这个开关（默认开着）。在 *标签试听器* 里能看到「朗读内容：…」那一行，确认实际会念什么。 |
| 提示「参考音频缺少对应文本」 | 参考音频模式必须填逐字转录。 |
| 听到的音色和参考音频完全不像 | 参考音频太长导致编码 OOM，s2.cpp 已静默回退成默认音色。截成 5–15 秒后重试；扩展也会弹警告。 |
| 弹窗提示「参考音频编码失败」 | 同上。展开 *引擎日志* 能看到 `encode failed` 和显存分配失败的原文。 |
| `.s2voice` 文件怎么都生成不出来 | 同上：`--save-voice` 只在参考音频成功编码后才写文件。参考音频过长 → 编码 OOM → 不写文件、也没有任何报错（退出码仍是 0）。 |
| 生成档案时提示「没有填写 s2.exe、模型和 tokenizer 路径」 | 面板里的档案生成需要 s2.exe 的命令行。打开 *服务进程*，把 `s2.exe`、GGUF 模型、`tokenizer.json` 填好（**DLL 目录**也要填，它是 CUDA 运行库所在的地方）。 |
| 生成档案失败 / 提示「failed to save voice profile」 | 扩展会先把档案写到纯 ASCII 的临时目录再搬过去，所以中文目录名本身不是问题。更常见的原因是参考音频太长导致编码失败——把选区缩到 5–15 秒再试。 |
| 生成档案卡在「正在加载模型」不动 | 每次生成都要重新加载一遍 5 GB 的模型，第一次要十几秒。看看任务管理器里是不是有第二个 s2.exe 进程在占内存。 |
| 合成出来是噪音 / 破音 | 参考音频转录和音频对不上，或者参考音频本身太短、含背景音乐。 |
| 合成明显偏慢 | Debug 构建的 s2.exe 实测 RTF≈3.9（比 Release 慢数倍）。重新编译 Release 版可显著提速。 |
| 启动 s2.cpp 报 DLL 缺失 | *DLL 目录* 没填或填错。CUDA 运行库一般在 CUDA Toolkit 的 `bin\x64` 下。 |

## 自测

```bash
node test/run.mjs
```

会依次验证：文本清洗的各种情况、服务端插件的路由注册、s2.cpp 的启动/停止、
`/status` 探测、音色列表，以及三次真实的 `/generate` 合成
（一次用超长参考音频断言会被标成编码失败，一次用短参考音频断言不会，
一次走流式中继），并检查返回的 WAV 确实是浏览器能解的格式、且不是静音。

流式那一次会断言：响应头是 `audio/L16` + `X-Audio-Encoding: pcm_s16le`、
带 `Cache-Control: no-transform`、分成多块到达、
**第一块在合成结束前很久就到了**。本机实测：

```
(first chunk after 1598 ms, whole stream took 14865 ms, 16 chunks)
```

最后还有一条断连回归用例：模拟"客户端在流到一半时消失、且 socket 缓冲区已满"，
断言转发协程会正常解开、不会再往一个已经走掉的客户端推数据。

缓存那组会断言：第一次请求是 `miss` 并落盘、**第二次同样的请求 3 秒内就返回且字节完全一致**
（证明没有重新合成）、换文本会 miss、`bypassCache` 会 miss、
关掉缓存会 miss、清空缓存后又会 miss。

队列那组（`queue.js`）会断言：任意时刻**只有一个任务在跑**、顺序不变、
**下一条必须等上一条真正播完**（用一个手动释放的"播放结束"闸门卡住它）、
停止时排队的条目全部以 `-1` 结算、可以单独取消某一条、
以及**一个失败的任务不会卡死整条队列**。

播放器那组（`player.js`）用一个假的 AudioContext 断言：
PCM 流被正确解码并调度到音频图上、**`waitForEnd()` 在音频节点真正 `onended` 之前不会兑现**、
调用 `stop()` 会兑现所有等待者、没有调度时立即兑现。

标签选音那组（`voicetree.js` + `plugin/voices.js`）会断言：
标签块只从回复开头切、冒号后面的台词原样保留、
「名字·性别·性格·语气」和「性别·性格·语气」两种写法都能解析、
**正文里的 `·` 不会被误吃**（不命中已知分类就整段保留）、
三级匹配从精确到宽松逐级放宽、文件夹里的 `默认` 优先、
目录树能被正确读出来（性别/性格/语气分别取自文件夹和文件名）、
以及**中文目录名的音节能被合成**（ASCII 中转的往返测试）。

朗读区间那组（`sanitize.js`）会断言：
默认的 `朗读` 表示朗读整条、首尾字符就是标记（`【朗读内容】` → `【`…`】`）、
占位符写法同样有效、只取标记之间的内容、
一条消息里的多个区间都会被取到、只写开始标记时取到消息结尾、
消息里没有区间时原样返回（由面板上的开关决定要不要退回整条）。

自定义音色那组（`plugin/voices.js`）会断言：
`.wav` / `.mp3` 和 `.s2voice` 都被认成音色、两者用 `kind` 区分、
`.txt` 不会被误当成音色、
**转录从同名 `.txt` 里读出来**、没有同名文件时转录为空、
转录可以被写回同名 `.txt`、
录音和档案一样按 性别/性格/语气 分类（所以标签能选中它）、
以及**录音的路径原样保留**（插件自己读字节再上传，路径根本不会经过 s2.cpp，
所以中文路径不会有 ANSI 问题）。

生成档案那组会断言：
`/voices/audio` 真的把录音的字节端出来（`RIFF` 头 + `audio/wav`）、
**音色目录以外的文件会被拒绝**（这个路由不能变成任意文件读取器）、
没有转录 / 档案名带路径分隔符 / 引擎路径不存在 / 发来的不是 WAV —— 都会被挡下来、
不存在的任务 id 返回 404、
然后是**真的跑一遍 `s2.exe --save-voice`**：任务会跑完、档案落到目标目录、
文件头是 `S2VOICE`、而且**这个新档案能直接拿来合成**（能出真实音频）。

> 这里踩到过一个坑：s2.cpp 存档案时用的是窄字符路径，
> 中文档案名会直接 `failed to save voice profile`。
> 扩展的解法和读档案时一样——**先写到纯 ASCII 的临时目录，再搬到目标目录**。

这一组不依赖 s2.cpp，可以单独跑：

```bash
node test/voicetree.mjs
```

生成档案的纯函数那组（`plugin/profile.js` + `profile.js`）也可以单独跑：

```bash
node test/profile.mjs
```

它会断言：档案名里的路径分隔符会被清掉（不能逃出音色目录）、
保留的 Windows 设备名会被改名、
命令行一定带 `--save-voice`、**一定跳过 `--codec-auto` 那个 17 秒的基准测试**、
模型留在 CPU 而编解码留在 GPU、
以及波形峰值、WAV 头（16 bit 单声道 PCM）、裁剪区间、混音这些都算对。

上面那两组（队列 / 播放器）同样可以单独跑：

```bash
node test/playback.mjs
```

扩展的 JavaScript 是浏览器加载的 ES 模块，`node --check` 把它当 CommonJS 会误报。
语法检查用模块解析器来做（只解析、不执行）：

```bash
node test/syntax-check.mjs
```

它会逐个解析仓库根目录和 `plugin/` 下的 11 个文件，任何一个语法错误都会报出来。

> 测试用的缓存目录是 `%TEMP%\s2tts-cache-test`，不碰你的真实缓存。
> 想改：`S2TTS_CACHE_DIR` 环境变量。

> 顺带修掉的一个真实问题：s2.cpp 同一时间只处理一个合成，连着点两条消息会拿到
> 503「忙」。**服务端插件现在会自己排队重试**（0.5 / 1 / 2 / 3 / 5 / 8 / 12 秒，
> 最多约 31 秒），扩展还有一层退避重试兜底，所以浏览器根本看不到这个 503。

> s2.cpp 的 busy 标志是在合成线程结束时才释放的，而 HTTP 响应在那之前就已经结束，
> 所以"紧接着再发一条"有大约几百毫秒的窗口会被拒。实测（Debug 构建）：
> 紧跟着的第二条请求拿到 503，再下一条就被接受了。

路径可用环境变量覆盖：`S2TTS_EXE`、`S2TTS_MODEL`、`S2TTS_TOKENIZER`、
`S2TTS_VOICE_DIR`、`S2TTS_DLL_DIR`、`S2TTS_REFERENCE`、`S2TTS_PORT`。

### s2.cpp 到底"忙"多久：`test/busy-probe.mjs`

```bash
node test/busy-probe.mjs
```

s2.cpp 同一时间只处理一个合成，第二个请求会拿到 503。但它的 busy 标志是在
**合成线程结束时**才释放的，而 HTTP 响应在那之前就已经结束——所以"紧接着再发一条"
有大约几百毫秒的窗口会被拒。这个脚本把缓存那一组请求按顺序重放一遍，并打印
s2.cpp 的引擎日志，用来确认这条链路。

---

### 克隆是否真的生效：`test/clone-proof.mjs`
这个脚本需要**已经跑起来的 SillyTavern**（它会调服务端的 `/logs` 路由）：

```bash
node test/clone-proof.mjs
```

s2.cpp 会打印 `Prefilling N tokens`，N 里包含参考音频编码出来的参考码。
所以只要对比三种请求的 N，就能确定克隆到底有没有被应用：

```
[no reference]             Prefilling 24 tokens
[short reference]          Prefilling 225 tokens   ← 克隆生效
[long reference (673 s)]   Prefilling 24 tokens    ← 编码 OOM，静默回退
```

> 别被 `ref_encode=0.000000 ms` 迷惑。按句拆分的服务端路径会在切句**之前**
> 单独把参考音频编码好，所以分段合成那一轮的指标里这个值是 0。
> 判断克隆有没有生效要看 prefill 的 token 数。

## 附：s2.cpp 返回的 WAV 格式

实测（`test/wav-format.mjs`）s2.cpp 的 HTTP 服务有两条输出路径，位深不一样：

| `stream` | `segment_sentences` | fmt | 位深 |
|---|---|---|---|
| `true` | `true` | 1 (PCM) | **16 bit** |
| `true` | `false` | 1 (PCM) | **16 bit** |
| `false` | `true` | 1 (PCM) | **16 bit** |
| `false` | `false` | 3 (IEEE float) | **32 bit** |
| 不传 | 不传 | 3 (IEEE float) | **32 bit** |

本扩展固定发送 `stream: true`，所以拿到的始终是 16-bit PCM，浏览器 `decodeAudioData` 直接就能解。
即便上游换了构建方式、返回 32-bit float，浏览器同样能解——不用改代码。

> 顺带说明：ComfyUI 那个插件的 `nodes.py` 里 32-bit WAV 是按**有符号整数**解码的
> （`np.frombuffer(frames, dtype="<i4")`），而 s2.cpp 的 32-bit 输出是 IEEE float。
> 不过该插件始终发送 `stream: true`，实际拿到的都是 16-bit，走的是 `width == 2` 分支，
> 所以那条链路没有问题。只有手动用 `stream=false` + `segment_sentences=false` 才会碰到。

## 附：在 ComfyUI 插件里手填这些路径

ComfyUI-FishS2-GGUF 的 **Scan Components 按钮扫不到 Debug 构建的 s2.exe**
（它只扫 `build/bin/Release/`、`build/Release/`、`build/bin/` 这几种 Release 布局），
所以下面几项需要手动填：

| 插件字段 | 填这个 |
|---|---|
| `executable` | `F:\s2\s2.cpp\build\Debug\s2.exe` |
| `dll_dir` | `F:\s2\bin\x64` |
| `model` | `F:\s2\s2.cpp\models\s2-pro-q8_0.gguf` |
| `tokenizer` | `F:\s2\s2.cpp\tokenizer.json` |
| `voice_dir` | `F:\s2\s2.cpp\voices` |

两点提醒：

1. **Debug 构建偏慢。** 本机实测 RTF ≈ 3.9（生成 13.9 秒音频要 65 秒），
   Codec 解码还要再花 20 秒。改成 Release 构建会快好几倍。
2. **插件的 Voice Create 节点在本机会失败。** 它的底层也是 `--save-voice`，
   而 `--save-voice` 只有在参考音频**成功编码**之后才会写文件——
   参考音频太长就会 OOM、然后既不报错也不生成文件。
   把参考音频截到 5–15 秒就能正常生成 `.s2voice`。
